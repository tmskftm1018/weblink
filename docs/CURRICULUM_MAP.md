# WebLink 학습 과정 지도

버전: 설계 기준 v1.1 / 콘텐츠 0.3.0 (부분 공개)
학생 화면 문구는 모두 한국어로 제공한다.

최신 묶음: M05 React 상태 목록+도서 전이, M06 실제 GET API, M07 실제 POST 검증+행사 신청 전이를 공개했다. M05는 App.jsx를 작성하고 제한된 React 렌더링 환경을 사용한다. M06/M07은 독립 FastAPI 서버와 HTTP 관찰 컨테이너로 실행하며 메모리 목록을 사용한다. 전체 frontend/backend 연결과 SQLite 영속 저장은 M08~M10에서 구현할 범위다. M08 이후는 준비 중이다.

최신 추가: M04를 공개했다. 제한된 동기 폼 환경에서 JS를 직접 작성하고 6개 입력의 저장 호출·오류 안내·입력 유지 결과를 비교한다. 8개 실행 판정과 개념/설명 제출을 기존 저장 흐름에 연결한다. M05~M12는 준비 중이다.

후속 추가: M03까지 공개했다. M03은 HTML 폼을 직접 작성하고 제한된 미리보기에서 관찰한다. 서버는 태그/속성, form, 제목/내용 입력, id, label 연결, 제출 버튼의 8개 구조 항목과 개념 질문을 검사한다. 실제 초점 이동·스크린리더·스타일 접근성 전체를 자동 판정하지 않는다. M04 이후는 준비 중이다.

2026-10-20 구현: M01/M02는 작성·저장·서버 재열기·개념 확인·제출을 연결했다. C00~C05는 정해진 브라우저 예제로 관찰하고 예측/관찰/개념 답안을 별도로 저장한다. M03~M12는 경로만 안내하고 시작 버튼은 비활성화한다. C 연습은 필수 미션을 대신하지 않으며, B 브리지의 프로젝트 개정 복귀는 기존 서버 기반만 있고 새 화면에는 아직 연결하지 않았다.

## 기본 원칙

- 첫 완성 경로는 `WEB-FS-01` 웹 풀스택 미니 게시판 한 과정이다. 목표는 UI → HTTP/API → 검증 → SQLite → 다시 UI로 이어지는 책임을 이해하고, 다른 문제로 옮기는 것이다.
- 코스는 **공통 기초 C → 웹 미션 M01~M12**로 진행한다. B 브리지는 진단 실패 또는 학습자 선택 시에만 삽입하고, 브리지 종료 후 원래 미션, 파일, 리비전, 작성 위치로 복귀한다.
- 진단은 설명량을 조정하지만 핵심 검사·설명·전이 증거를 면제하지 않는다. AI를 쓰거나 쓰지 않는 선택은 점수와 권한에 영향을 주지 않는다.
- 현재 5개 코스/37개 수업은 게시판 코스와 동일한 교과로 보지 않는다. 기존 lesson slug와 사용자의 진도는 유지하고, 콘텐츠를 확인한 뒤 재사용 가능한 내용만 매핑한다.
- JSON의 `prerequisites`는 필수 미션 선행 관계, `foundation_ids`는 관련 기초 지식, `recommended_bridge_ids`는 필요할 때 선택하는 보충 경로다. 브리지를 모든 학습자에게 필수로 강제하지 않는다.

## 학습 여정 ID (J)

`J00` 목표·도움 방식 선택 → `J01` 짧은 사전 진단 → `J02` 경험 수준 제안/수정 → `J03` 코스 선택 → `J04` 학습 워크스페이스 생성 → `J05` 미션 시작 → `J06` 브리지 잠깐 학습 → `J07` 원래 미션 복귀 → `J08` 코드/산출물 저장 → `J09` 실행과 실제 관찰 → `J10` 기능·개념·전이 평가 → `J11` 설명·포트폴리오·독립 응용.

여정 단계는 UI 흐름 ID이며 코스 수업을 대신하지 않는다. 중단 후 복구는 `journey_state` 및 마지막 미션 개정/열린 파일에 연결한다.

## 레거시 45차시 보존·매핑

v1.1 설계서가 제안한 장기 카탈로그는 다음 45 슬롯이다. 현재 저장소에서 이 45개 각각의 과거 제목/ID를 독립적으로 입증하는 원본 명세는 찾지 못했으므로, 아래는 **슬롯 분포와 새 경로로의 매핑 기준**이며 미검증 제목을 새로 만들어 넣지 않는다.

## 현재 코스와 새 코스의 관계

- 기존 코스/레슨/진도는 삭제하지 않는다.
- 기존 5개 코스의 37개 수업은 프로젝트 API 연결과 SQLite/Google Sheets 등 구체적 연습을 포함한다. 현재 자료만으로 각 옛 차시를 45개 legacy 슬롯과 일대일 대응하는 것은 근거가 부족하다.
- 기존 수업 중 변수/조건/반복/DB/API/오류 개념이 새 C/B/M과 정확히 일치하면 내용과 테스트를 비교하고 재사용 후보로 제안한다. 이름이 비슷하다는 이유만으로 완료 이력을 새 미션 완료로 바꾸지 않는다.
- 기존 연결 실습은 M12 이후 선택형 응용 코스/확장 카탈로그로 이동 가능하다. 이는 사용자 진도 이력과 데이터 삭제 없이 화면 분류/노출을 바꾸는 작업이다.

## ID 규칙

- 사용자 여정: `J00..J11`
- 단원: `U-WEB-01..04` (4개 학습 단계)
- 신규 코스: `WEB-FS-01`
- 공통 기초: `C00..C05`; 브리지: `B-*`
- 미션: `M01..M12` (저장 키는 항상 코스 ID와 결합)
- 검사/문항/전이 예: `WEB-M04-T1`, `WEB-M04-Q1`, `WEB-M10-X1`
- 콘텐츠/루브릭은 각각 독립 version을 사용. 기존 UUID 및 slug는 수정/재사용하지 않는다.


## 2026-10-20 추가 반영 · SQLite 저장과 API 재시작

- 공개 범위: M01~M09. M10~M12는 초안이다. 기존 등록·답안·평가 데이터와 콘텐츠 버전 0.3.0은 유지했다.
- M08: 격리된 main.py가 /data/learning.db에 posts(id, title)를 만들고 두 제목을 저장한다. 별도 검사 컨테이너가 실제 행·고유 ID를 읽고 INSERT의 ? 매개변수 문법을 정적으로 확인한다. 정적 문법 확인은 실제 실행된 SQL 전체의 안전성을 입증하지 않는다.
- M09: M07 입력 검증을 유지한 FastAPI에 실제 GET/POST를 보내고, 별도 검사기가 같은 SQLite 파일을 읽는다. worker가 서버를 실제 재시작한 뒤 새 GET 응답과 DB 행을 관찰한다. 제출에는 이 저장본의 12개 실행 항목과 개념/서술 응답이 필요하다.
