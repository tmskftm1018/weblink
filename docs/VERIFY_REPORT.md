## 이번에 확인한 회귀 조건

- 미공개 과정은 실제 HTTP 목록/상세/등록에서 노출되지 않는다. 비로그인 요청은 401, 다른 계정의 등록 읽기/변경은 404다.

- 브리지 진입 시 원래 미션/개정/파일/커서를 서버가 별도 저장한다. 브리지에서 새 개정으로 작업하고 새 세션에서 다시 열어도 복귀점이 유지된다.
- B-HTTP의 기본 추천 지점이 M06이어도 실제 M07에서 들어가면 M07로 복귀한다.
- 다른 프로젝트 개정과 없는 파일은 거부한다. 원본이 삭제되면 해시·기록은 보존하되 복귀 성공을 꾸며내지 않는다.
- 클라이언트는 평가 통과값이나 브리지 원본 해시/복귀 미션을 직접 지정할 수 없다.

- 기존 버전 복원에서 오래된 초안 버전은 409, 현재 버전은 정상 복원된다.

## 2026-10-19 로컬 인증 오류 대응

- 후속 API 로그에서 로그인 200 직후 학습 요청 401이 반복됐다. 실행 중 web의 API 주소는 LAN IP였고 사용자는 localhost로 접속했다. 단순 만료로 단정한 초기 설명을 정정한다. 쿠키가 같은 사이트에서 전달되도록 Docker web의 API 주소를 상대 경로로 바꾸고 Vite `/api` 프록시를 API 서비스에 연결했다. 일반 로컬 개발 프록시는 localhost:8000을 기본으로 사용한다.
- 로그인 안내 문구에는 별도 여백·폭·줄 간격을 지정해 본문과 겹치지 않게 했다. 웹 컨테이너만 재생성했다. 실제 사용자 계정의 로그인 성공 여부는 아직 확인하지 않았다.
- 학습·프로젝트·연결 앱의 HTTP 401을 공통 감지해 한국어 재로그인 안내를 표시한다. 작성 상태는 메모리에 남기며 기존 계정으로 재인증하도록 제한한다. 새로고침 시 미저장 내용이 사라질 수 있음을 안내한다.
- Docker CLI가 현재 PATH에서 확인되어 `docker compose up --build -d web`으로 web과 의존 API를 반영했다. API 준비 상태 200 및 PostgreSQL의 0042 → 0043 → 0044 마이그레이션 완료 로그를 확인했다.
- 이번 인증 변경의 브라우저 재로그인 동작과 별도 TypeScript 빌드/테스트는 수행하지 않았다. 컨테이너 시작 성공을 해당 동작 검증으로 간주하지 않는다.

## 2026-10-20 추가 반영 · SQLite 저장과 API 재시작

- 공개 범위: M01~M09. M10~M12는 초안이다. 기존 등록·답안·평가 데이터와 콘텐츠 버전 0.3.0은 유지했다.
- M08: 격리된 main.py가 /data/learning.db에 posts(id, title)를 만들고 두 제목을 저장한다. 별도 검사 컨테이너가 실제 행·고유 ID를 읽고 INSERT의 ? 매개변수 문법을 정적으로 확인한다. 정적 문법 확인은 실제 실행된 SQL 전체의 안전성을 입증하지 않는다.
- M09: M07 입력 검증을 유지한 FastAPI에 실제 GET/POST를 보내고, 별도 검사기가 같은 SQLite 파일을 읽는다. worker가 서버를 실제 재시작한 뒤 새 GET 응답과 DB 행을 관찰한다. 제출에는 이 저장본의 12개 실행 항목과 개념/서술 응답이 필요하다.
- 연습 DB는 실행별 격리된 16MiB tmpfs Docker 볼륨이다. 별도 제한된 keeper 컨테이너가 마운트를 유지해 API 재시작 중에도 파일이 남는다. 전체 실행이 끝나면 정리한다. 답안·결과는 WebLink PostgreSQL에 유지된다. 장치 종료를 견디는 사용자 프로젝트 영구 DB라고 표현하지 않는다.
- 화면에서 실제 SQLite 행, 재시작 후 행, 마지막 GET 응답을 비교할 수 있다. 코드 내려받기·저장 충돌·기존 실행 기록 재사용 흐름을 재사용했다.
- M10 React→HTTP→SQLite 통합은 아직 미구현이다. 현재 React 실행기는 외부 I/O가 없는 QuickJS이므로 HTTP를 흉내 내 통합 성공으로 표시하지 않는다. 다음 묶음에서 두 파일 스냅샷과 실제 제한된 HTTP 연결 경계를 구현해야 한다.
- 확인: TypeScript/Vite production build 성공(기존 Monaco 큰 청크 경고), 변경 Python Ruff 통과, 커리큘럼 구조 검사 통과, Docker 이미지 재빌드 및 서비스 시작. 자동 테스트와 실제 학습 답안/E2E/격리 공격 검증은 실행하지 않았다.

- 창별 sessionStorage 복구본을 유지하면서 계정/등록/미션별 localStorage 복구를 추가했다. 창별 복구본을 우선하며 다른 창의 복구본과 내용/기준 버전이 다르면 저장 완료나 폐기 시 지우지 않는다. 기기 간 동기화나 서버 백업은 아니다.
- 복구본이 남아 있으면 편집을 잠시 막고 비교/가져오기/다운로드/폐기를 제공한다. 서버 버전이 달라졌다면 다른 항목마다 선택을 요구하고 자동 저장하지 않는다.
- 저장 409 시 최신 서버 답안과 원래 입력을 비교할 수 있다. 선택 후에도 현재 서버 버전을 기반으로 저장하므로 그 사이 다시 바뀌면 기존 낙관적 잠금이 차단한다. 비교 기능은 기존 저장 API를 재사용한다.
- localStorage 실패 시 창별 보관만 가능함을 알리고 두 저장소 모두 실패하면 다운로드/서버 저장을 안내한다. 같은 브라우저의 복구본은 사용자 구분을 하지만 브라우저 자체의 보안 저장소는 아니며 공용 기기에서는 정리가 필요하다.
- 학습 실행 결과를 닫았다가 메모리에 있는 결과를 다시 펼친다. 재실행이나 미션 완료 기록을 만들지 않는다. 네트워크 실패와 로그인 만료를 한국어로 안내한다.
- 자동 테스트와 실제 두 창 충돌/재로그인/저장소 차단 시나리오는 이번 묶음에서 실행하지 않았다. 최초 TypeScript/Vite 빌드 성공, 기존 Monaco 대형 청크 경고가 남았다. 최종 변경의 빌드/컨테이너 반영은 아래 후속 기록으로 남긴다.
- 최종 TypeScript/Vite 프로덕션 빌드 성공(기존 Monaco 청크 경고 유지). 웹 컨테이너만 재빌드·재기동했다. 백엔드와 데이터베이스 변경은 없다. 실제 복구/충돌 브라우저 시나리오는 아직 확인하지 않았다.


## 2026-10-21 · 프로젝트 보존과 협업 충돌 복구

- 앞선 학습 답안 보관을 공통 browserDrafts 저장 모듈로 분리해 학습/프로젝트가 함께 사용한다. 기존 학습 키와 구조는 유지하며 프로젝트에는 수정 전 기준 파일을 추가한다. 프로젝트별 hook과 비교 컴포넌트를 분리했다.
- 프로젝트 편집 시 기준 버전/기준 파일/수정 파일을 브라우저에 보관한다. 계정/프로젝트 키를 분리하며, 다른 창이 만든 내용이 다른 복구본을 저장 완료 시 삭제하지 않는다. sessionStorage를 우선하고 localStorage 복구도 지원한다. 여러 창의 모든 독립 수정본을 영구 보관하는 서버 버전 관리 기능은 아니다.
- 프로젝트 재진입, 저장 충돌 후 최신 초안 비교, 수정본 JSON 가져오기가 같은 3방향 파일 비교를 사용한다. 파일 추가/삭제도 포함하며 같은 파일을 양쪽에서 바꿨을 때는 선택을 요구한다. 복구본 적용은 편집기만 바꾸고 자동 저장을 멈춘다. 명시적 저장은 기존 초안 버전 검사/권한 검사로 처리한다.
- 수정본 JSON은 서버 저장 없이 내려받을 수 있다. 가져오기는 format/version/project ID와 안전한 경로, 50개 파일, 파일당 200,000자, 전체 1MB를 확인한다. 원본 비교 기준도 같은 한도로 확인한다. 새 서버의 별도 DB로 옮기는 기능은 아니며 같은 프로젝트에만 적용한다. JSON 안의 임의 파일 코드는 이 과정에서 실행하지 않는다.
- 모달에서 내려받기/편집기 가져오기/서버 파일 선택/목록 복귀를 제공한다. 브라우저에 보관할 수 없으면 복구본 유지 목록 복귀는 막고 다운로드를 안내한다. 비교/복구 자체는 연결 PC 폴더를 변경하지 않으며 명시적 초안 저장 시에는 기존 폴더 저장 동작을 유지한다.
- 저장 전 새로고침 경고와 로그아웃 전 저장을 추가하고 저장 실패/충돌이면 로그아웃하지 않는다. 프로젝트 저장 진행 중 주요 메뉴 이동을 막는다. 401/403/409를 구분하고 409 해결 화면으로 연결한다.
- TypeScript/Vite 빌드 성공. 기존 Monaco 큰 청크 경고가 남는다. 자동 테스트와 실제 두 계정·동시 수정·새로고침·JSON 왕복·권한 회수·저장소 부족 시나리오는 이번 묶음에서 실행하지 않았다.
- 최종 수정의 TypeScript 검사와 웹 컨테이너 재빌드·재기동을 완료했다. DB 마이그레이션/사용자 데이터 변경/자동 테스트/commit/push는 수행하지 않았다.

## 2026-10-21 · 최근 작업 위치와 프로젝트 실행 기록

- 프로젝트 위치 저장/조회 서비스와 전용 hook, 프로젝트 실행 조회 hook과 기록 선택 컴포넌트를 분리했다. 기존 기능인 개요 기본 진입과 명시적 학습 브리지 이동을 유지한다.

- 이미 있던 실행 목록/단건 API를 연결했다. 백엔드의 현재 사용자/프로젝트 접근 및 requested_by 필터를 사용하며 다른 팀원의 실행 기록을 공유하는 기능은 아니다. 목록은 최근 30개다.

## 2026-10-21 · 파일 탐색과 변경 검토

- 프로젝트 파일 목록 검색과 현재 초안 내용 검색을 추가했다. 검색어는 정규식 특수 문자를 문자로 처리하고 서버/외부로 전송하지 않는다. 대소문자 구분/경로 포함 필터, 줄별 첫 일치, UTF-16 기준 줄/열 이동, 검색 미리보기 강조를 제공한다. 최대 200줄을 반환하며 초과 표시를 분리한다.

- 기존 복구 baseline과 파일 비교 helper를 재사용해 서버 저장 전 변경을 표시한다. 자동 저장 일시 중지는 기존 pause 상태를 사용하고 명시적 초안 저장 성공 시 다시 시작한다. 수정이 없는 상태에서는 바로 자동 저장을 켤 수 있다. 복구나 서버 최신 변경 병합 기능을 새로 만들지 않았다.
- Monaco 읽기 전용 diff를 요청할 때만 로딩한다. 추가/삭제/빈 파일을 상태로 구분하며 기본은 한 열이고 사용자가 나란히 보기를 선택할 수 있다. 편집 모델과 비교 모델은 서로 다른 URI를 사용한다. 파일 트리/탭 표시도 파일별 차이에 맞게 수정했다.
- TypeScript/Vite 빌드 성공(기존 Monaco 청크 경고). 자동 테스트와 실제 검색/단축키/포커스/비교/모바일 브라우저 시나리오는 이번 묶음에서 실행하지 않았다.
- 최종 TypeScript 검사와 웹 컨테이너 재빌드·재기동 완료. DB 변경과 commit/push는 수행하지 않았다.

## 2026-10-21 · 실제 브라우저 및 두 계정 통합 점검

기존 사용자 계정과 진도를 수정하지 않고 확인용 계정의 새 프로젝트에서 점검했다. 일반 로그인과 HTTP API를 사용했으며, 임시 계정의 비밀번호·세션·점검 스크립트는 저장소에 포함하지 않는다.

### 발견하여 수정한 문제

- Vite /api 프록시의 WebSocket 전달을 활성화하고 소켓 URL 프로토콜을 정규화했다. 수정 후 팀 화면의 현재 접속 표시를 확인했다.
- 홈에서 내 프로젝트를 눌렀을 때 배우기에 남던 이동 경로를 수정했다. 홈 디자인은 변경하지 않았다.
- 복구본을 유지하며 목록으로 돌아갈 때 최신 목록을 조회하고 이전 프로젝트 안내를 정리하도록 공통 목록 로딩을 재사용했다.
- 마지막 파일 삭제 후 저장이 422로 실패하던 제약을 수정했다. 초안에 빈 파일 목록을 허용하며 가져오기의 최소 파일 제약은 유지한다. 확인용 프로젝트에서 빈 저장→재조회→빈 revision→원래 파일 재추가 저장을 API로 확인했다. 파일이 없는 상태의 브라우저 삭제 조작은 별도 수행하지 않았다.

### 실제 확인 범위

- 브라우저: 프로젝트 생성, 자동 저장 일시 중지, 코드 수정/미저장 표시, Ctrl+Shift+F 리터럴 검색([a+b]), 검색 결과 파일 열기, Ctrl+P 파일 이동, 수정 전후 비교, 명시적 저장, 실행 성공/출력, 결과 닫기와 재실행 없는 다시 열기, 최근 작업 복귀.
- 브라우저 및 두 계정 API: 편집자 동시 수정 후 실시간 충돌 안내, 오래된 버전 저장 409, 복구본 유지 목록 이동, 새로고침 후 복구본 재발견, 같은 파일의 내 수정 선택, 서버에서만 바뀐 README 보존, 병합 후 v3 저장. HTTP 재조회로 내 코드와 팀원 README가 함께 저장됐음을 확인했다. 병합 후 브라우저에서 새 실행을 요청하여 완료/종료 코드 0을 확인했다.
- API 권한: 미참여 프로젝트/다른 계정 비공개 프로젝트/타인의 실행 기록 404, 보기 전용 읽기 허용 및 초안 저장·revision 생성·팀 관리 403, 소유자 강등 400, 잘못된 상대 경로·중복 경로 422, 로그아웃 후 me 401. 점검 후 팀원은 편집 권한으로 복원했다.
- 결과 다시 열기 전후 실행 수가 1개로 유지되는 것을 API로 확인했다. 이후 병합본의 새 실행은 명시적으로 요청한 별도 실행이다.
- 최종 TypeScript 검사/Vite 프로덕션 빌드 성공. 기존 Monaco 대형 청크 경고는 남는다. 웹/API 컨테이너 반영과 readiness ready/database ok를 확인했다.
