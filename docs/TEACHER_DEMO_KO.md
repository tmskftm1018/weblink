# 교수님께 보여 줄 대표 학습 시연

## 소개

“코드는 작성했지만 앱으로 연결하기 어려운 학습자가, 화면의 입력이 API와 DB를 거쳐 저장되는 과정을 연습하는 사이트입니다.”

발표에서는 Google·GitHub 연동이나 팀 관리 대신 학습자가 무엇을 만들고 어떻게 잘못된 동작을 고치는지 보여 준다. 화면 디자인은 별도 작업이다.

## 시연 준비

- 실제 사용자 계정의 기록 대신 확인용 계정을 사용한다. 기존에 완료한 미션을 DB에서 강제로 해제하거나 완료 증거를 만들어 넣지 않는다.
- 과목과 난이도를 선택한다. 대표 시연은 입문 수준으로 하되 기본·경험자 설정과 제공 코드 차이를 짧게 보여 준다.
- 처음 시작하는 수업에는 `practice-v2`가 적용된다. 기존 작성 중 수업은 화면의 ‘작성 내용 유지하고 실습 방식으로 전환’을 사용한다. 완료한 수업은 기존 기록을 유지한다.
- 실제 시연할 미션까지 선수 조건을 정상적으로 완료한다. M10은 앞 수업의 API와 React를 연결하는 통합 단계다.

## 대표 시연 순서

1. **누가 무엇을 배울지:** 관심 과목과 난이도를 설정한다. “이번에 만들 결과”와 “이렇게 나오면 돼요”를 읽는다.
2. **작은 실패 확인:** M05에서 글 누적 처리가 빠진 코드를 실행한다. 저장·실행·확인을 한 버튼으로 진행하고, 실제 실패한 검사 항목을 본다.
3. **원인을 좁히기:** “결과가 다르면 먼저 확인할 것”과 단계별 힌트를 본다. 배열 갱신과 입력 초기화를 수정한 뒤 같은 검사를 다시 실행한다. 힌트 사용으로 감점하지 않는다.
4. **학습 부담 차이:** 예측·관찰을 매번 긴 문장으로 작성하지 않아도 된다. 추가 기록은 선택 메모에 남기고 개념 확인은 짧은 선택으로 진행한다. 코드 검사 결과를 대신 작성해 주거나 통과를 자동으로 인정하지 않는다.
5. **연결의 결과:** M10에서 화면 입력 → API 요청 → SQLite 저장 → 조회와 재시작 후 복원을 확인한다. React Test Renderer 검사는 실제 브라우저 시연과 구분해서 설명한다. 내려받은 앱의 브라우저 시연은 별도로 직접 검증한 경우에만 성공했다고 말한다.
6. **다른 문제에 적용:** M12에서 메모장·할 일 앱에 같은 원리를 적용하는 목표를 보여 준다. 모든 수준에서 두 앱을 확인하며 UI·API·DB의 역할은 한 번 정리한다.

## 학생에게 확인할 질문

- 등록 버튼을 눌렀을 때 화면은 어떤 요청을 보내는가?
- 정상 입력인데 목록이 바뀌지 않으면 어느 부분부터 볼 것인가?
- 새로고침이나 서버 재시작 후에도 글이 남으려면 어디에 저장해야 하는가?

친구가 직접 실습하도록 한 뒤 첫 성공까지 걸린 시간, 막힌 지점, 도움을 받은 뒤 스스로 수정했는지를 기록한다. 이 관찰 없이 학습 효과가 검증됐다고 주장하지 않는다.
