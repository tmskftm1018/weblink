# WebLink 디자인 기준

2026-10-01 공개 디자인 시스템과 현재 WebLink 화면을 함께 검토해 정리한 기준이다. 특정 사이트의 화면을 복제하지 않고, 학습·프로젝트·외부 연결이 한 제품 안에서 자연스럽게 이어지도록 공통 패턴을 골라 적용한다.

## 참고한 디자인 시스템

- [GitHub Primer 레이아웃](https://primer.style/product/getting-started/foundations/layout/): 먼저 해야 할 일에 집중하도록 화면을 정돈하고, 읽는 흐름에 맞춰 내용을 배치한다. 긴 설명은 적절한 본문 폭을 유지하고, 좁은 화면에서는 여러 열을 단일 열이나 별도 보기로 전환한다.
- [GitHub Primer 컴포넌트](https://primer.github.io/design/components/): 페이지 제목, 하위 내비게이션, 액션 바, 트리, 빈 화면, 알림처럼 실제 제품 작업에 필요한 컴포넌트의 역할을 구분한다.
- [Atlassian 내비게이션 레이아웃](https://atlassian.design/components/navigation-system/layout): 전역 내비게이션, 화면 제목과 주요 액션, 본문을 분리해 화면의 구조를 먼저 읽을 수 있게 한다.
- [Carbon 간격 기준](https://carbondesignsystem.com/elements/spacing/overview/): 4·8·12·16·24·32px 리듬을 사용해 요소 간 관계와 중요도를 나타낸다. 모든 영역을 같은 간격과 같은 카드로 감싸지 않는다.
- [Carbon 그리드](https://carbondesignsystem.com/elements/2x-grid/overview/): 넓은 화면은 콘텐츠 목적에 맞춰 열을 나누고, 작은 화면에서는 열 수와 영역 배치를 바꾼다.
- [Material Design 3 대표 레이아웃](https://m3.material.io/foundations/layout/canonical-examples/overview): 화면 폭과 사용 맥락에 따라 같은 콘텐츠의 배치를 바꾼다.

## WebLink에 적용하는 원칙

1. 학습 화면은 수업과 실습을 중심에 둔다. 프로젝트 화면은 파일·작업·팀 협업을 중심에 둔다.
2. 프로젝트 개요는 소개, 핵심 숫자, README, 진행 상황 순서로 읽히게 한다. README 본문 폭은 읽기 편하게 제한하면서 카드 자체는 중앙에 둔다.
3. 프로젝트 편집 화면에는 현재 프로젝트 이름과 저장 상태를 먼저 보여준다. 실행과 변경 저장은 바로 보이는 위치에 두고, 버전 저장·ZIP 내보내기·삭제는 `더 보기`에 모은다. 삭제는 메뉴 안에서 위험 동작으로 구분한다.
4. 프로젝트 안의 개요·코드·작업·팀·저장 위치는 같은 위치와 모양의 하위 탭으로 이동한다.
5. 같은 역할의 버튼, 입력, 카드, 알림에는 같은 높이·색·테두리·간격을 쓴다. 한 화면에서 강한 카드와 그림자 수를 제한한다.
6. 넓은 화면은 그리드를 활용하되 문장과 README를 과도하게 길게 늘이지 않는다. 좁은 화면에서는 읽기 순서를 유지하며 열을 쌓고 메뉴를 화면 안에 둔다.
7. 색은 의미를 전달할 때 쓴다. 초록은 주요 동작과 성공, 빨강은 오류·삭제, 중립색은 보조 정보에 사용한다.

## 이번 화면 수정

- 전역 상단 메뉴를 단순한 텍스트 내비게이션으로 바꾸고 현재 위치는 밑줄로 표시한다.
- 버튼 높이와 입력 테두리를 통일하고, 보조 버튼은 중립 테두리형으로 정리한다.
- 프로젝트 목록 카드의 밀도와 간격을 조정하고 사용 가능한 저장 위치 설명을 최신 기능에 맞춘다.
- 프로젝트 편집 헤더에서 실행과 저장을 우선 배치하고, 덜 자주 쓰는 작업은 한 메뉴로 모은다.
- 프로젝트 내부 탭을 한 줄 하위 내비게이션으로 바꾼다.
- README와 개요 콘텐츠 칼럼을 페이지 중앙에 제한된 폭으로 두고, 소개·요약·문서·진행상황의 간격을 다시 맞춘다.
- 학습, 프로젝트, 연결 화면에 공통 페이지 여백·표면·테두리·버튼 기준을 적용한다.

## 상태

이번 변경은 화면 코드에 반영했지만 브라우저에서 시각 확인하거나 프로덕션 빌드를 실행하지 않았다. 먼저 프로젝트 목록, 프로젝트 개요, 코드 편집, 작업 보드, 연결 화면을 데스크톱과 모바일 폭에서 확인한다.
