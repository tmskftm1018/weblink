# WebLink 홈페이지 전용 프롬프트

현재 프로젝트의 실제 기능과 구조를 먼저 살펴본 뒤, 아래 기준에 맞춰 WebLink의 공개 홈페이지를 구현하거나 다듬는다.

## 제품 설명

WebLink는 블록 활동에서 시작해 Python 학습, 프로젝트 파일 편집·실행·디버깅, 팀 작업, API·데이터베이스·Google Sheets 연결까지 이어지는 교육용 개발 플랫폼이다. 소개와 기능 카드는 이 프로젝트에 이미 구현된 기능만 설명한다. 아직 지원하지 않는 기능, 고객사, 후원사, 성과를 만들어내지 않는다.

## 시각적 방향

- [Pixel Network](https://pixelnetwork.kr/) 홈페이지에서 느껴지는 단정한 브랜드 소개와 여백, 부드러운 섹션 이동의 감각을 참고한다. 레이아웃·문구·이미지·로고를 그대로 복제하지 않고 WebLink 고유의 스타일로 재구성한다.
- 오프화이트, 절제된 세이지 그린, 짙은 잉크색을 중심으로 미니멀하고 정돈된 기술 제품의 인상을 만든다.
- 큰 제목을 남발하지 않는다. 첫 화면의 WebLink 워드마크도 화면을 압도하지 않도록 세련된 크기와 절제된 굵기로 표시한다.
- 네트워크를 연상시키는 장식은 브랜드 글자와 경쟁하지 않도록 최소한으로 사용한다. 첫 화면에는 별도 장식, 설명, 보조 문구, 버튼을 두지 않는다.
- 고정형 상단 바는 로고와 메뉴(소개, 기능, 기술 스택), 로그인 진입을 제공한다.

## 화면 순서와 내용

1. **Hero** — 첫 화면의 콘텐츠는 가운데 놓인 `WebLink` 한 단어뿐이다. 타이틀 외에 설명, CTA, 장식 그래픽은 표시하지 않는다.
2. **소개** — WebLink의 목적을 간결하게 설명하고 `블록 학습 → 코드 작성 → 프로젝트 실행 → 데이터 연결`의 흐름을 보여준다.
3. **핵심 기능** — 블록으로 배우기, 프로젝트 만들고 실행하기, 팀과 작업 정리하기, API·DB·Sheets 연결하기를 목적별 카드로 소개한다. 카드는 기존 가입 흐름으로 연결한다.
4. **기술 스택** — 큰 홍보 카피나 긴 설명은 두지 않는다. 짧은 제목 `WebLink를 만든 기술`과 역할별 그룹을 보여준다. 기술은 사용 언어(Python, TypeScript), 프런트엔드(React, Monaco Editor), API·외부 연동(FastAPI, Google Sheets API), 데이터베이스(SQLite, PostgreSQL), 실행 환경(Docker)으로 구분한다. 그룹은 같은 디자인 규칙을 적용해 기술 쇼케이스처럼 정돈하고, 사용자가 사이트 안에서 이 기술을 직접 쓸 수 있다는 의미로 표현하지 않는다.

기술 스택 아래에는 `이제 직접 만들어 볼 차례예요`라는 짧은 CTA와 기존 WebLink 가입으로 이어지는 버튼을 두고 간결한 푸터로 마무리한다.

## 스크롤과 동작

- 각 섹션은 한 화면에 가깝게 구성하고 고정 헤더 메뉴를 누르면 해당 섹션으로 부드럽게 이동한다.
- 데스크톱에서는 휠 한 번에 섹션 하나만 약 0.9초의 부드러운 ease-in-out 전환으로 이동해 화면이 자석처럼 정렬되어 멈추는 느낌을 준다. 전환 중 연속 휠 입력은 한 번의 동작으로 처리하되, 도착 후 다음 입력은 답답하지 않게 빠르게 받는다.
- 작은 화면에서는 콘텐츠를 읽기 위해 섹션이 화면보다 길어질 수 있게 하고, 자연스러운 터치 스크롤을 지원한다.
- `prefers-reduced-motion` 환경에서는 움직임을 줄인다.

## 구현 조건

- 프로젝트의 기존 React·TypeScript·Vite 구조를 사용한다. 독립 HTML을 새로 만들거나 기존 앱을 불필요하게 재작성하지 않는다.
- 랜딩은 비로그인 첫 화면으로 제공하며, 기존 로그인·가입 및 인증 후 앱 흐름을 보존한다. 인증 화면에서는 홈으로 돌아올 수 있게 한다.
- 모바일 반응형 레이아웃, 시맨틱 HTML, 키보드 포커스 표시, 명확한 한국어 버튼 이름을 지원한다.
- 새 의존성은 추가하지 않는다.
- 구현 후 TypeScript/Vite 프로덕션 빌드를 실행해 확인하고, 빌드할 수 없으면 이유와 미확인 사항을 명시한다.
