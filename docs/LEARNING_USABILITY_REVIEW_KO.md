# 학습 화면 사용성 검토 · 2026-11-02

## 판정

글을 줄인 이전 변경만으로 충분하지 않았다. 선택 체험이 실습 버튼을 밀어내고 통합 과제의 편집기 네 개가 동시에 펼쳐져 있었다. 휴대폰에서는 수업 목록이 목표보다 먼저 나왔다. 직접 관찰한 혼란 요소를 수정했지만, 실제 초보자의 독립 완주나 학습 효과를 검증한 결과는 아니다.

## 확인 방법

- localhost의 실제 브라우저에서 기존 확인용 계정을 사용했다. 새 계정을 만들거나 기존 완료 기록을 지우지 않았다.
- M01의 입력 부담, M04의 구현 안내, M10의 초기 화면·편집·필수 응용·구현 조건, M12의 필수 응용·연결 설명을 확인했다.
- 데스크톱 1280×720, 휴대폰 너비 390×844에서 관찰했다. 측정 후 브라우저 크기 설정을 원복했다.
- 확인 계정은 참고 답안으로 이미 12/12를 완료했다. 빈 미션의 첫 작성 과정과 사람의 이해도는 이번 검토에 포함하지 않는다. 아래 수치는 해당 계정·펼침 상태의 화면 측정값이며 모든 환경의 고정값이 아니다.

## 여전히 어려운 부분

1. **첫 성공 전 설정 부담:** M01은 목표·경험·도움 방식 3개, 진단 3개, 개념 답 1개와 저장/다시 열기 절차가 필요하다. 설정에서 학습의 재미를 느끼기 어려울 수 있다. 기존 진단/과제 기준을 임의 삭제하지 않았다.
2. **수업 내용의 난이도:** React 상태, 비동기 HTTP 요청, API 입력 검증, SQL을 함께 다루는 M10·M12는 사전 지식이 부족하면 어렵다. 화면 접기만으로 개념 간격이 해소되지는 않는다.
3. **첫 수정 지점의 실제 이해:** 수정 동작 안내를 구체화했지만, 초보자가 제공 코드에서 위치를 찾아 직접 바꿀 수 있는지는 관찰이 필요하다. 참고 답안 통과는 이를 증명하지 않는다.
4. **서비스 첫 소개의 불일치:** 홈은 아직 블록/Python과 Google Sheets를 중심으로 설명한다. 현재 화면·API·DB 연결 과정과 첫인상이 다르다. 친구 담당인 홈 디자인은 이번 검토에서 수정하지 않았다.

## 다음 사람 테스트

초보자 한 명에게 설명을 대신해 주지 않고 M04를 진행하게 한다. 무엇을 만들지 자신의 말로 설명할 수 있는지, 실제 코드 편집을 찾는지, 공백/정상 입력의 차이를 이해하는지, 실패 후 스스로 돌아가 수정하는지를 기록한다. 이어 M10에서는 화면·API·DB 중 어느 부분의 문제인지 찾을 수 있는지 확인한다. 완료 시간·도움을 요청한 지점·예시와 실제 실행을 혼동했는지를 기록하고, 그 관찰로 수업을 다시 나눈다.

## 2026-11-02 · 입문 연결 예제의 빈칸 줄이기

- 기존 입문 M12 API는 주석 위주의 뼈대여서 입력 검증·테이블·조회까지 다시 구현해야 했다. 새 입문 M10/M12 시작 예제는 이미 배운 조회·입력 검증·화면 상태를 준비하고 POST 요청과 DB 저장의 TODO에 집중하게 한다. 미완성 UI는 등록 미연결 오류, 미완성 API는 501을 반환하며 정상 저장을 가장하지 않는다. 기본/경험자 제공 코드와 필수 응용·기능 검사는 유지한다.
- 시작 예제 개정 guided-20261102를 새 입문 M10/M12 과제에 기록하고 과제 키에 포함했다. 기존에 저장한 과제에는 개정을 끼워 넣지 않으며 기존 시작 코드·답안과 M09 API 상속을 보존한다. 경로 변경 후 저장된 예제 기준 유지와 이전 키의 첫 저장 충돌도 테스트했다.
