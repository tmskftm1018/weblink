# 학습 시스템 아키텍처 제안

버전: G0 설계 초안
목표: WebLink의 기존 프로젝트 제품과 저장 구조를 유지하면서 v1.1 학습 경험을 별도 계정별 학습 공간으로 제공한다.

## 추천하는 학습 경험

PDF의 큰 구조(C 기초 → 필요 지점의 B → 누적 프로젝트 M → 기능/개념/전이 평가)를 유지한다. 다음 개선을 더한다.

1. **첫 출시는 M01~M12 한 과정을 완성한다.** 기존 45 슬롯과 37개 수업은 검증·매핑 전까지 별도 이력으로 보존한다.
2. **한 화면의 기본 행동은 하나로 제한한다.** 학생에게 현재 목표, 성공 증거, 지금 할 행동만 전면에 표시하고 자세한 설명·로그·전체 학습 지도를 접을 수 있게 한다.
3. **검사 결과는 코드 개정·루브릭 버전에 묶는다.** 코드 또는 루브릭 변경 즉시 과거 통과는 `STALE`가 된다. worker/API 장애는 `UNAVAILABLE`로 남기고 학생의 실패 횟수나 평가로 세지 않는다.
4. **진단은 학습량을 줄일 뿐 증거는 면제하지 않는다.** 경험자는 설명을 건너뛸 수 있어도 기능·개념·지정 전이 검사 결과를 제출한다.
5. **AI 사용은 수업 외부의 선택 도구다.** 사용자가 자신의 CLI/사이트에 직접 로그인하고, WebLink는 선택된 범위만 미리보기 후 복사한다. WebLink 서버가 AI에게 문제를 보내거나 AI 답으로 진도를 판정하지 않는다.

## 컴포넌트와 책임

```text
React Learning UI
  ├─ 여정/코스 지도, 현재 행동 1개, 한국어 수업 문구
  ├─ HTML/JS 연습기와 React/Web 미션 작업공간
  ├─ 실행·검사 상태 (관측/미관측 분리), H1~H4 힌트
  └─ 선택적 CLI/사이트 맥락 미리보기와 수동 복사
             │ authenticated /api/v1/learning/*
             ▼
FastAPI learning service
  ├─ 버전형 LessonSpec 읽기 + 시작 시 스키마 검증
  ├─ 진단/브리지/복귀 및 사용자별 저장·복원
  ├─ 검증된 테스트 registry로 검사 요청
  └─ 정해진 규칙으로 상태 전이 (AI 호출 없음)
             │
             ├─ PostgreSQL: WebLink 운영 계정·코스 진도·검사 메타데이터
             └─ 격리된 학습 workspace: 코드 revision / 수업용 SQLite 데이터

Worker / isolated runner
  ├─ 읽기 전용 입력 revision + 리소스 제한 실행
  ├─ 허용된 파일만 검사, 네트워크 기본 차단
  └─ 실행 로그를 짧고 민감정보 마스킹하여 결과에 첨부
```

코드 실행은 FastAPI 본 프로세스에서 하지 않는다. 기존 Worker/Docker 경계가 새 과정을 만족하는지 먼저 검사한다. 특히 Docker 소켓 보유·연결 앱 네트워크 예외는 G5 threat review 없이 넓히지 않는다. 보안된 브라우저/worker 경로가 준비되지 않으면 해당 자유 코드 검사/실행 UI를 제공하지 않고 고정 템플릿 실습으로 제한한다.

## 콘텐츠 계약

학생이 보는 한국어 수업과 실행 로직은 별도 버전 데이터로 관리한다. 제안하는 JSON/타입 필드:

```text
course_id, lesson_id, unit_id
content_version, rubric_version
title, objective, prerequisites
prediction, explanation_cards, micro_practice
student_task, starter_workspace, target_files
expected_observation, test_ids, concept_check_ids, transfer_check_ids
hint_ids (H1..H4), recovery, next
```

- `test_ids`, `concept_check_ids`, `transfer_check_ids`, `hint_ids`, `target_files`가 실제 registry/workspace와 연결되지 않으면 콘텐츠 검증 오류다.
- 학습 위치의 파일 경로는 workspace root 기준 정규 상대경로여야 하며 해당 개정에 실제로 존재해야 한다. 향후 실행/AI 내보내기에는 별도 allowlist와 비밀 제거가 필요하다. 일반 프로젝트의 기존 파일 저장 정책은 이 문서만으로 바꾸지 않는다.
- 테스트 본문과 판정 코드는 사용자가 제출한 JSON/코드에서 가져오지 않는다. 서버의 신뢰된 registry가 실행할 검사 버전을 선택한다.
- 교재 변경은 기존 완주 이력을 삭제하지 않고 content version을 올린다. 평가 기준이 바뀌면 rubric version을 올리고 새 증거를 요구한다.

## 검사·상태 계약

상태 집합: `NOT_STARTED`, `IN_PROGRESS`, `FUNCTION_PASSED`, `NEEDS_REVISION`, `UNAVAILABLE`, `STALE`, `TRANSFER_PENDING`, `COMPLETED`.

- **RUN**: 학습자가 요청한 실제 프로그램 실행. 실행과 로그/관찰을 기록하지만 자동으로 미션을 통과시키지 않는다.
- **CHECK**: 신뢰된 테스트 묶음을 지정된 revision/rubric에서 실행하고 각 ID의 결과를 기록한다.
- **SUBMIT**: 기능 결과 + 필수 구조화 개념 문항 + 지정된 전이 근거를 묶어 완료 조건을 서버가 평가한다.
- `COMPLETED`는 서버 측 규칙만 만든다. AI 대화, 화면 버튼, 브라우저 전달 status로 완료 상태를 저장하지 않는다.
- 핵심 검사를 재시도할 수 있다. 힌트/AI를 사용한 횟수로 점수나 권한을 낮추지 않는다.
- 열린 파일·편집 위치·마지막 revision·bridge return target은 복귀/복구에 필요한 최소 정보만 저장한다.

## 저장·계정 분리 제안

현재 `Course`, `Lesson`, `LearningProgress`, `LearningEvidence`는 그대로 유지한다. 새 커리큘럼을 위한 추가 저장 테이블은 Alembic `20261019_0043`에서 추가한다.

| 엔티티 | 핵심 키/자료 | 규칙 |
| --- | --- | --- |
| `LearningEnrollment` (구현) | user, course key/content/rubric version, 연결 project, 현재 node·bridge 복귀점, 마지막 revision/hash | 계정·과정 버전별 단일 등록; 기존 `LearningProgress`와 분리 |
| `LearningAssessmentEvidence` (구현) | 등록, 미션/평가 ID와 유형, content/rubric version, revision/hash, 상태, 구조화 payload | 기능·개념·관찰·전이 결과를 같은 계정 영역에 기록. `UNAVAILABLE`/`STALE`은 오답으로 처리하지 않음 |
| `Project` / `ProjectRevision` (재사용) | WebLink 파일 저장, revision snapshot 및 source hash | 중복 파일 저장소를 새로 만들지 않음. 프로젝트 삭제 시 FK는 비우고 관측 당시 revision hash와 평가 결과는 남김 |
| `LessonSpecVersion` (아직 미구현) | 안정적인 course/lesson/unit ID와 정적 콘텐츠 버전 | JSON 초안이 현재 source of truth. 검증 통과와 publish gate를 거친 뒤 DB/UI/API에 노출 |
| 검사 registry (아직 미구현) | 평가 ID와 신뢰된 검사 코드 경로 | 브라우저가 전달한 `PASSED` 값을 신뢰하지 않고, 서버가 등록된 검사로 판정 |

현재 개인 학습 프로젝트는 본인 소유만 허용한다. 0044는 브리지 원본 개정/해시/파일/커서를 마지막 편집 위치와 별도로 보존한다. 진입/반복 저장/종료는 서버 저장 상태에 따라 검증하며 클라이언트가 복귀점을 지정할 수 없다. SQLite와 실제 HTTP 인증/격리 테스트, 0042→0044 PostgreSQL 오프라인 SQL 생성은 이전에 통과했다. 로컬 PostgreSQL은 0045까지 적용했으며, 코드 편집 UI 복귀와 RUN/CHECK 판정 registry는 미완료다.

콘텐츠 구조 검증은 `app/content/curriculum/validation.py`에서 통일한다. 0.3.0은 `partial` 공개를 허용하며 준비된 미션의 선수 미션도 공개되어야 한다. 완전 `published` 상태에는 여전히 모든 미션이 공개되어야 한다. M01/M02는 신뢰된 `artifact_checks.py`의 산출물 검사만 실행하고 나머지 미션은 draft다. 등록 경로나 파일 존재만으로 실행 통과를 주장하지 않는다.

### 2026-10-20 산출물 학습 연결

#### M05~M07 묶음 (최신)

- M05: React/React Test Renderer 18.3.1과 esbuild 0.21.5를 별도 빌드 단계에서 묶는다. 학습 JSX를 변환한 뒤 호스트 입출력 API가 없는 QuickJS에서 실제 useState/onChange/onSubmit과 렌더 결과를 관찰한다. 브라우저 DOM 전체는 실행하지 않으며 웹에는 허용한 태그/속성의 읽기 전용 스냅샷만 렌더링한다. [React Test Renderer 문서](https://legacy.reactjs.org/docs/test-renderer.html)를 확인했다.
- React state 배열은 학습용으로 freeze해 직접 변경 오류를 알린다. 빈 값/공백 거부, 두 항목 추가, 순서 보존, 입력 보존, 오류 메시지, 새 컴포넌트의 메모리 초기화를 검사한다. 도서 목록은 독립 JSX 소스와 실제 실행 결과를 전이 증거로 저장한다.
- M06/M07: 기존 privileged worker의 Docker 연결을 재사용한다. 새 `LearningExecution`(0046)에 저장본 해시/버전/소스/노드/전이 구분을 묶어 대기시킨다. 사용자당 동시 대기/실행은 2개로 제한하고 결과 조회는 소유 사용자만 허용한다. 기존 실행 큐와 새 큐를 한 worker 루프에서 처리한다.
- 매 실행마다 내부 전용 네트워크, 읽기 전용 소스 볼륨, 별도 학습자 FastAPI 서버 컨테이너와 신뢰된 HTTP 관찰 컨테이너를 만든다. 검사기는 학습자 Python을 import하지 않고 실제 HTTP 요청만 보낸다. 두 컨테이너는 별도 PID/파일 시스템이며 소스 컨테이너에는 Docker 소켓, DB/Google/AI 비밀값을 전달하지 않는다.
- 학습자 서버는 비루트/읽기 전용/capability 제거/no-new-privileges, 128MiB/0.5CPU/PID32 제한이고 검사기는 64MiB/PID8이다. 실행이 끝나면 임시 자원을 제거하고, 중단 잔재는 전용 라벨·만료 기준으로 회수한다. 개인 프로젝트의 영속 데이터 볼륨을 정리 대상으로 삼지 않는다. 구성은 격리 검증 완료의 증거가 아니다.
- M06의 실제 GET 상태/JSON 배열/형식/반복 조회와 M07의 정상/거부/최대 길이 경계/잘못된 요청 저장 방지/GET 재조회를 검사한다. 행사 신청 전이는 `/api/registrations`, name 1~40자로 별도 실행한다. 현재 데이터는 실행별 메모리이며 DB 영속 저장은 M08부터다. [FastAPI 요청 본문](https://fastapi.tiangolo.com/tutorial/body/), [상태 코드](https://fastapi.tiangolo.com/tutorial/response-status-code/)를 참고했다.
- 실행 큐는 lease token으로 오래된 worker 결과를 거부하고 중단은 UNAVAILABLE로 보존한다. 같은 저장본의 결과를 재사용할 수 있으므로 화면은 ‘실행 기록’으로 표시한다. 기다리기 중지는 브라우저 대기만 중단하며 서버 작업 종료를 꾸미지 않는다. 제출은 서버가 보관한 현재 해시의 검사 결과만 사용하고 클라이언트가 성공값을 보내지 않는다.
- M05/M07은 기능·개념·설명·실행 전이를 모두 갖춰야 완료된다. 자유 서술은 작성 요건만 검사하며 설계 품질을 자동 평가했다고 주장하지 않는다. M05와 M06/M07의 실제 frontend/backend 통합은 아직 연결하지 않았으며 M10의 범위다.

#### 후속 M04 실행 연결

- `learning-runner`는 API와 분리한 내부 전용 서비스다. `python-quickjs-ng==0.12.1.1`을 고정해 사용하고 Python 호스트 콜백/파일/네트워크 기능을 JS에 노출하지 않는다. [패키지 문서](https://pypi.org/project/python-quickjs-ng/0.12.1.1/)와 [프로젝트 문서](https://github.com/Marven11/python-quickjs-ng)를 확인했다.
- 요청마다 별도 Python 프로세스에서 QuickJS 컨텍스트를 생성한다. JS 컨텍스트 메모리 16MiB, 스택 256KiB, 호출당 CPU 0.2초, 프로세스 CPU 2초/주소공간 160MiB/실제시간 3초 한도를 설정했다. Docker는 비루트, 읽기 전용, capability 제거, no-new-privileges, 256MiB, 0.5CPU, PID 32개를 설정했다. 이 설정만으로 격리 보안 검증을 완료했다고 주장하지 않는다.
- 외부 공개 포트/마운트/Docker 소켓/자격증명이 없고 API와 내부 네트워크로만 연결한다. API는 저장된 M04 source 하나만 전달한다. 브라우저 쿠키, 프로젝트 파일, CLI/API 비밀키를 전달하지 않는다.
- 지원 범위는 querySelector/getElementById, 동기 submit 이벤트, value/textContent, preventDefault, 관찰용 savePost({title, content})다. 실제 브라우저 DOM·비동기 요청·외부 통신·DB 저장은 지원하지 않는다. savePost 호출은 실제 프로젝트 저장과 구분한다.
- 빈 값/공백/탭·줄바꿈/한글/앞뒤 공백을 포함한 6개 입력마다 새 컨텍스트를 사용한다. 기본 제출 중단·거부·정상 호출·trim·오류 안내·입력 보존·오류 초기화 등 8개 판정을 반환한다. 각 실제 검사 ID와 답안 해시로 제출 증거를 남긴다.
- 실행 버튼은 현재 초안을 저장한 뒤 관찰 결과만 제공한다. 제출 버튼은 서버가 저장본을 다시 실행한 뒤 개념/작성 답안과 함께 판정한다. 실행기 장애는 UNAVAILABLE/HTTP 503으로 기록하며 오답이나 새 통과로 만들지 않는다. 문법/실행 오류와 자원 한도는 별도 표시한다.
- 현재 서비스 기동과 정적 검사는 확인했지만 실제 학습자 코드 실행·경계·부하/복구·브라우저 E2E 검증은 미실시다. API 단독 실행에서 runner URL이 없으면 실행을 제공하지 않는다. Docker에서는 전체 compose 실행 시 runner도 시작된다.

후속 M03 구현: 같은 산출물 저장을 재사용해 HTML source를 저장한다(최대 32,000자). `html_form_checks.py`는 HTMLParser로 구조만 파싱하고 학습자 스크립트를 실행하지 않는다. 허용 태그/속성, 요소 수/중첩 한도와 8개 실제 검사 ID를 사용하며 개별 판정을 기존 증거 테이블에 기록한다. 입력 파싱은 실제 브라우저의 DOM/접근성 판정과 구분한다.

## HTTP 계약과 실습용 SQLite

- 학습 프로젝트에서 단일 prefix `/api/posts`를 사용한다. GET은 200 + JSON 배열, POST는 성공 201, 잘못된 제목은 422다.
- 제목은 trim 후 1~80자를 API/Pydantic에서 확인한다. SQLite에서도 `CHECK`를 두고 모든 값을 parameter binding으로 쓴다.
- API 성공 뒤 목록은 GET으로 재조회한다. 실패하면 입력을 보존하고 관측된 오류를 설명한다.
- 학습 SQLite 파일은 계정/학습 워크스페이스마다 분리하며, 플랫폼 PostgreSQL/프로젝트 협업 DB와 혼합하지 않는다.
- 데이터 흐름 도식은 “예시”로, 실제 요청·응답/SQL 확인은 “관찰됨”으로 표시한다. 로그가 수집되지 않았다면 “미관측”이다.

- 새 LearningProjectExport와 추가형 migration 0047: enrollment/node/field마다 한 프로젝트만 만들고 최초 학습 hash/version과 프로젝트 revision/hash를 기록한다. PostgreSQL 등록 행 잠금과 고유 제약으로 반복 요청에 사본이 늘어나지 않도록 구성했다. 프로젝트·출처·연결·RECORDED 증거는 한 트랜잭션으로 저장한다. 프로젝트를 삭제했거나 소유권이 달라졌다면 자동 재생성하지 않고 안내한다.
- 다시 누르면 기존 본인 소유 프로젝트를 연다. 이후 학습 답안이나 프로젝트 변경은 자동 덮어쓰지 않으며 학습 원본과 달라졌다는 안내를 프로젝트 화면에 표시한다. 학습의 통과 판정을 새 프로젝트 실행 통과로 복제하지 않는다.
- 생성 파일: 원본 API, import/export만 덧붙인 React App.jsx와 원본 JSX, 한국어 README, Vite·React 진입 파일, Python/Node Dockerfile, compose.yaml, 출처 JSON 등이다. 사용자 코드와 생성한 앱을 main API에서 실행하지 않는다. 로컬 포트는 화면 5174/API 8081이며 SQLite는 별도 named volume으로 보관한다. WebLink의 기존 Python 실행 버튼으로 이 전체 앱을 실행한다고 안내하지 않는다.
- 처음 만든 프로젝트만 기본 학습 연결에 사용한다. 이후 생성한 학습 프로젝트는 사용자가 명시적으로 연결을 바꿀 수 있다. 다른 사용자/팀 편집 권한만 있는 프로젝트로 연결하지 않는다. 브리지 진행 중 연결 변경은 차단한다.
- 브리지는 연결 프로젝트의 확정 revision에서 파일·줄을 선택하고 현재 위치를 보관한 뒤 추천 개념/기초 예제를 표시한다. 복귀 시 원래 revision/file/line을 읽기 전용 Monaco에서 연다. 최신 프로젝트 편집기를 여는 동작은 별도이며 원래 snapshot으로 파일을 덮어쓰지 않는다. 미저장 내용과 리비전으로 확정하지 않은 초안은 브리지 원점에 포함하지 않는다.
- M10에는 HTTP/React/SQL, M12에는 디버깅 브리지를 추천했다. 기초 예제를 보는 것은 미션 완료나 자동 진도 증가가 아니다. 활성 브리지를 마친 뒤 미션을 이동하도록 안내한다. 서버의 기존 origin 보존/복귀 검증을 재사용한다.
- Monaco에 선택 줄 이동/커서 관찰을 추가하고 학습에서 최신 프로젝트 편집기로 이동할 때 경로와 줄을 전달한다. 원래 파일이 삭제됐다면 첫 파일을 열고 안내한다. 기본 프로젝트 진입은 기존 개요 화면을 유지한다.
- 전체 학습 기록 JSON에는 프로젝트로 가져온 출처 revision/hash도 포함한다. 개인 프로젝트 생성·브리지 접근은 계정별 등록과 OWNER 권한으로 제한한다.
- 확인: 웹 TypeScript/Vite build 성공(기존 Monaco 큰 청크 경고), 새 Python/변경 학습 서비스 Ruff 및 Python 구문 컴파일, 커리큘럼 구조 검사 통과. Docker 이미지 재빌드와 서버 시작을 수행했다. 자동 테스트와 실제 프로젝트 생성·동시 요청·ZIP 앱 실행·브리지 복귀·권한/E2E 검증은 수행하지 않았다.


## 추가 반영 · 학습 변경 반영과 실행 기록 다시 열기

- M10/M12의 프로젝트 변경 비교·반영을 연결했다. 관리 대상은 App.jsx, API, 원본 JSX와 출처 JSON 네 파일이다. 나머지 프로젝트 파일과 실행 설정은 보존한다.
- 이전에 가져온 학습 기준/현재 서버 프로젝트/새 학습 원본을 비교하고 양쪽 변경은 파일별 KEEP_PROJECT 또는 USE_LEARNING 선택을 요구한다. 프로젝트에서 지운 파일도 변경으로 취급한다. 미전송 로컬 폴더와 다른 창의 미저장 내용은 비교 대상이 아니다.
- 미리보기의 초안 version과 전체 프로젝트 hash, 현재 학습 version을 적용 시 다시 확인한다. 등록/초안 행 잠금·낙관적 조건 갱신을 사용한다. 동시 revision 저장의 고유 제약 충돌은 rollback 후 409로 안내한다.
- 반영 전 서버 초안을 revision으로 보관하고 변경 후 revision/RECORDED 출처/기준을 한 트랜잭션에 기록한다. 코드 변경이 없고 이미 같은 기준을 확인했다면 중복 기록을 만들지 않는다. 프로젝트 실행 통과를 자동 부여하지 않는다.
- migration 0048은 nullable baseline_files JSON만 추가한다. 기준은 병합 결과가 아닌 새 학습 원본이다. 이번에 유지한 프로젝트 수정을 다음 반영에서 덮어쓰지 않도록 계속 로컬 변경으로 취급한다. 이전 export는 최초 revision에서 기준을 읽으며 이 기준이 없으면 반영을 보류한다.
- M06~M12의 계정별 최근 30개 실행 목록과 기존 실행 ID 조회/기다리기를 연결했다. 결과 다시 열기는 새 실행을 큐에 넣지 않는다. 현재/과거 답안 구분, 기다리기 중지 후 재조회, 개별 JSON 내려받기를 제공한다. M04/M05 직접 실행에는 이 큐 기록 목록이 없다.
- 현재 코드/답안과 다른 결과는 과거 저장본으로 표시한다. 실행의 순진한 UTC timestamp는 API에서 UTC offset을 붙여 날짜 표시 오해를 줄였다.
- 확인: TypeScript/Vite build, 변경 학습 Python Ruff/구문 컴파일, Docker 서비스 시작, DB head 0048과 readiness를 확인했다. 기존 Monaco 큰 청크 경고는 남아 있다. 자동 테스트를 새로 추가/실행하지 않았고 실제 병합/충돌/복원/학습 완주는 실행 검증하지 않았다.


## 사용자 요청으로 확인용 예제 계정에서 추가 확인

기존 사용자 계정과 진도를 수정하지 않고 별도 로컬 예제 계정을 만들었다. 점수/완료 상태를 DB에 직접 넣지 않았으며 실제 HTTP 저장·실행·제출로 준비했다. 계정 비밀번호·세션과 임시 예제 준비 스크립트는 저장소에 포함하지 않는다.

- M01~M12를 실제 API로 순서대로 저장/실행/제출하여 12개 완료를 확인했다. M04 8개, M05 본/도서 전이 각 8개, M06 4개, M07 본/행사 전이 각 9개, M08 5개, M09 12개, M10 본/재고 전이 각 14개, M11 수정본 14개와 실패 재현본 11/14, M12 메모/할 일 각 14개 관찰 결과를 확인했다. M11의 재현본은 일부 항목 실패가 정상인 예제다.
- 같은 M10/M12 프로젝트 가져오기를 다시 호출해 created=False로 기존 프로젝트 재사용을 확인했다.
- M12 학습 코드와 프로젝트 API를 각각 수정하여 CONFLICT를 관찰했다. 프로젝트 API 유지 선택으로 반영한 뒤 직접 추가한 주석과 별도 문서 파일이 유지되는 것을 확인했다. 오래된 미리보기 재적용은 409로 차단됐다. 다음 학습 변경에서도 이전에 유지한 프로젝트 수정이 CONFLICT로 남는 것을 확인했다.
- 메모장 프로젝트를 명시적으로 연결하고 B-DEBUG 진입/복귀로 같은 revision/file/5번 줄이 복구되며 프로젝트 파일은 바뀌지 않는 것을 API로 확인했다. 저장된 실행 GET은 14개 관찰 결과를 반환했다.
- 브라우저에서 확인용 계정의 12/12 표시, M12의 현재/이전 실행 선택, 변경 비교와 파일 충돌 선택 화면을 확인했다.
- 생성된 프로젝트 파일을 별도 로컬 Docker Compose로 빌드·기동했다. 메모장 화면에서 입력→저장→목록 표시→브라우저 새로고침 후 데이터 유지를 확인했다. 이 구성은 localhost:5174(화면)/8081(API)이며 WebLink 서버와 별도로 실행한다.

이 기록은 한 확인용 계정과 준비한 예제의 제한된 확인이다. 모든 미션을 브라우저 폼으로 처음부터 작성한 완주, 동시 사용자/권한 공격·격리 한도·장치 재부팅·모바일·임의 학습 코드까지 검증한 것은 아니다. pytest 전체 회귀 검사를 새로 실행한 기록도 아니다. 과정은 partial로 유지한다.
