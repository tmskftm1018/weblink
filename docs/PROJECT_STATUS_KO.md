## 2026-10-30 · 저장된 실행 근거로 연결 흐름 확인

- 저장하지 않은 수정, STALE, 미저장 답안에는 현재 결과로 실행 근거를 표시하지 않는다. 자료가 없는 과거 기록에 실행 결과를 만들어 넣지 않는다. 정답·완료·실행 영수증·저장 해시는 변경하지 않았다.

- 실제 브라우저에서 QA 계정의 M10 저장된 POST 201·요청/응답·DB·재시작 결과, M07의 POST 422 안내, M11 실패 재현본의 실패 항목, 기존 실행 기록 복원을 확인했다. 코드에 임시 미저장 주석을 넣고 편집 반영을 기다린 뒤 현재 근거 숨김을 확인했고, 원문으로 되돌린 뒤 다시 표시되는 것을 확인했다. 이 검증 중 새 실행이나 학습 답안 저장은 하지 않았다.
- 디자인/CSS·API·외부 연동·Git commit/push 변경 없음. 전체 수업의 브라우저 완주와 실제 학습자 관찰은 남아 있다.

## 기존 기능 정리

아래는 기존 프로젝트·연결 기능의 정리이며, 새 통합 학습의 완주 검증 결과와 구분한다.

## 만들고 있는 제품

WebLink은 코딩 문법을 익히는 데서 멈추지 않고, 프로젝트를 API·데이터베이스·외부 앱과 연결하는 과정을 배우는 교육용 개발 플랫폼이다. 블록 활동으로 시작한 코드를 실제 프로젝트로 옮기고, 저장·실행·디버깅·데이터 연결까지 이어가는 방향으로 개발 중이다.

## 현재 구현된 기능

- 이메일 가입 및 로그인, 세션 관리
- 5개 학습 코스, 총 37개 수업과 사용자별 진행도 저장
- 코드 블록 순서 조립, 사용 블록 표시, 오답 힌트
- 프로젝트 생성, 파일 편집, 1.5초 입력 중단 후 자동 초안 저장과 수동 저장, 리비전 및 명명된 버전 관리. 저장 실패·최신 초안 충돌 시 자동 재시도를 멈추고 문제를 표시
- 프로젝트 목록에서 실행 가능한 SQLite 독서 기록 예제를 한 번에 만들고, 여러 파일로 데이터베이스 사용 흐름을 확인
- 프로젝트 파일 탐색기에서 폴더를 만들고 접고 펼치며, 파일을 끌어 폴더 간 이동하거나 프로젝트 루트로 다시 꺼낼 수 있음. PC의 UTF-8 텍스트 파일과 폴더도 루트나 폴더에 끌어 넣을 수 있고, 폴더 구조와 빈 폴더를 유지함. 파일당 200KB·전체 1MB·최대 50개 제한과 비밀 파일 차단을 적용. 폴더 안에 바로 새 파일을 추가하고 빈 폴더는 `.gitkeep` 파일로 ZIP·Git 저장 시 유지
- VS Code 기반 Monaco 코드 편집기: 문법 강조, 줄 번호, 파일 탭, 검색, 저장·실행·탭 닫기 단축키
- 파일 탐색기에서 새 파일을 추가하고 열어 둔 파일 탭을 선택하거나 닫을 수 있음
- 파일 탐색기에서 파일 이름을 바꾸거나 삭제할 수 있고, 연결한 로컬 폴더에도 같은 파일 작업을 반영. 같은 이름이 있으면 `도구 (2).py`처럼 번호를 붙이며, 실행 시작 파일 `main.py`도 이동·이름 변경·삭제 가능
- 폴더 이름을 바꾸거나 삭제할 수 있음. 이름 변경 시 내부 파일 경로와 연결한 컴퓨터 폴더도 함께 갱신하고, 삭제 시 안의 프로젝트 파일과 빈 폴더를 정리. 확인창에서 삭제 범위를 먼저 안내
- 프로젝트 소유자는 가입된 WebLink 이메일로 팀원을 바로 추가하거나 7일 유효 초대 링크를 만들 수 있음. SMTP를 설정하면 링크를 이메일로 보내고, 설정이 없거나 전송에 실패하면 초대 링크를 복사해 직접 전달할 수 있음. 링크는 지정된 이메일로 로그인한 사용자가 직접 수락하며 한 번만 사용 가능. 편집자·보기 전용 권한 지정 및 팀원 제거를 지원. 다른 팀원의 저장·프로젝트 정보·권한을 10초 간격과 창 복귀 시 확인해 화면에 반영하며, 내 코드가 저장되지 않은 상태면 덮어쓰지 않고 최신 초안 확인을 안내. 글자 단위 실시간 공동 편집은 아직 지원하지 않음
- 프로젝트 소유자는 팀 화면에서 생성한 초대의 이메일·권한·만료일·대기/만료 상태를 확인하고 대기 중 초대를 취소하거나 만료 기록을 정리할 수 있음. 만료된 초대는 같은 이메일과 권한으로 바로 재발급할 수 있고, 만료 기록 삭제는 팀 변경 기록에 취소로 남지 않음. 취소한 링크는 즉시 수락할 수 없음
- 프로젝트 초안·팀·작업 변경을 접속 중인 팀원에게 WebSocket 알림으로 전달하고 기존 프로젝트 조회 API로 최신 내용을 즉시 갱신. 팀 화면에 현재 접속 중인 팀원을 표시하며, 연결이 끊겨도 기존 10초 주기 갱신과 창 복귀 확인이 대체 경로로 동작
- 프로젝트별·이메일별 초대는 한 건만 유지하며, 재발급하면 기존 링크는 무효화됨. 동시에 초대를 요청해 중복 초대가 만들어지는 경우도 데이터베이스 제약으로 막음
- 프로젝트 팀 화면에서 팀원 추가·제외, 권한 변경, 초대 생성·재발급·취소·수락 기록을 프로젝트 구성원이 확인할 수 있음. 최근 100건을 보관하며 작업 상태 변경 기록과는 별도 범위임
- 프로젝트 소유자는 이름과 설명을 수정하고, 팀원의 편집자·보기 전용 권한을 필요할 때 바꿀 수 있음. 이름과 설명 수정은 프로젝트 초안 버전을 건드리지 않음. 접근이 해제되거나 프로젝트가 삭제되면 저장되지 않은 코드를 복사할 수 있도록 안내하고 프로젝트 목록으로 이동 가능
- 프로젝트 안에 할 일·진행 중·완료 작업 보드를 제공. 제목·설명·담당자·우선순위·마감일 필터와 ‘내 작업’ 보기를 지원하고, 전체 완료율·진행 중·기한 초과 개수를 요약 표시. 내 작업 중 기한 초과·7일 내 마감 항목으로 바로 이동할 수 있음. 최근 100개 활동을 알림 패널에서 확인하고 항목을 누르면 해당 작업으로 이동. 읽음 상태는 현재 브라우저의 사용자·프로젝트별 로컬 저장소에 저장하므로 다른 브라우저나 컴퓨터와 공유되지 않음. 작업별 체크리스트(최대 30개), 댓글, 생성·상태·담당자·우선순위·마감일·체크 항목 변경 기록을 확인. 댓글과 기록은 프로젝트 팀원에게 보이고, 댓글 작성과 작업 관리는 편집자·소유자만 가능. 작업은 프로젝트당 200개 제한이며, 팀원 제외 시 담당 해제 기록과 함께 담당자 없음으로 전환
- 프로젝트 첫 화면에 소개·최근 활동·파일/작업/팀원/저장 버전 요약을 보여주는 대시보드를 제공. 최근 활동을 누르면 관련 작업 기록으로 이동하며 읽음 상태를 작업 보드 알림과 공유. 루트 `README.md`의 Markdown과 안전 허용 목록에 포함된 기본 HTML을 미리 보고 편집기로 이동할 수 있으며, README가 없으면 소개와 파일 목록을 담은 초안을 만들 수 있음. 스크립트·이벤트 속성·임의 스타일은 실행하지 않음. 코드 편집·작업 보드·팀 관리·저장 위치를 별도 구역으로 열 수 있어 한 화면에 모든 도구가 길게 쌓이지 않으며, 구역을 바꿔도 작업 보드 입력과 열린 패널 상태는 유지
- 학습 화면의 수업 본문 폭을 읽기 좋은 범위로 제한하고 코스 목록은 화면 안에서 스크롤되도록 구성. 연결 화면도 프로젝트 화면과 같은 페이지 폭·여백을 사용하며, 스프레드시트 ID와 범위 입력을 넓은 화면에서는 나란히 표시하고 모바일에서는 세로로 배치
- 보기 전용 계정은 화면과 API 양쪽에서 파일 변경·저장·실행·버전 변경을 제한. 편집자와 소유자는 초안 저장·버전 관리·실행 가능하고, 프로젝트 삭제와 팀원 관리는 소유자만 가능
- 저장 버전마다 만든 사람과 저장 날짜를 표시. 오래된 화면에서 복원을 요청하면 최신 초안 버전을 서버에서 대조해 팀원의 최근 저장 내용을 덮어쓰지 않도록 충돌 안내
- 루트 `main.py`가 없으면 실행 버튼을 비활성화하고 복구 방법을 안내. 이동·이름 변경·삭제 전에도 실행에 미치는 영향을 확인
- 실행 결과 패널 닫기, 디버깅 가설 저장 버튼 안내, 리비전 내역을 화면에서 숨김
- 프로젝트 목록 화면을 저장 위치 안내, 검색, 생성·가져오기, 프로젝트별 저장소 상태를 확인하는 작업 공간으로 개편
- 프로젝트 목록의 시각적 우선순위를 조정해 프로젝트 카드를 중심에 두고, 새 프로젝트·ZIP 가져오기는 요청할 때 열리는 폼으로 변경. 저장·공유 안내는 접어서 필요할 때 확인
- 프로젝트 목록에 이름 검색, 최근 수정순·이름순 정렬, 내가 소유한 프로젝트·참여 중인 프로젝트 필터 추가
- 프로젝트 목록 카드를 화면 폭에 따라 여러 열로 배치하고, 검색·필터 결과가 없을 때 초기화 버튼을 제공
- GitHub 공개·비공개 저장소의 기본 브랜치를 가져와 새 프로젝트를 만들 수 있음. Fine-grained token은 연결 암호화 키로 사용자별 암호화 저장하고 화면에 반환하지 않음. 프로젝트는 원본 저장소·브랜치·커밋을 기억하고 새 변경 확인 및 수동 가져오기를 지원. 가져오기 전에 현재 WebLink 초안을 명명된 저장 버전으로 백업하고, 버전 충돌이 생기면 적용을 막음. 연결된 컴퓨터 폴더는 자동 수정하지 않으며 GitHub push 동기화는 아직 없음. 저장소 ZIP은 1.5MB 제한
- Google Picker에서 사용자가 선택한 Drive 텍스트/Markdown/CSV/HTML/CSS/JSON 파일 또는 Google Docs·Sheets를 최대 50개까지 한 프로젝트로 가져올 수 있음. 파일당 200KB, 전체 1MB 제한과 중복 파일명 자동 번호 추가를 적용. OAuth는 제한된 `drive.file` 권한을 사용
- 프로젝트 편집기에서도 Google Drive에서 최대 50개 파일을 골라 현재 프로젝트에 추가 가능. 기존 파일과 이름이 겹치면 자동으로 번호를 붙이고, 초안 저장 전에는 WebLink 서버에 반영하지 않음
- 프로젝트 실행 코드에서 `weblink_api.update_google_sheet(spreadsheet_id, range, rows)`로 편집 가능한 Google Sheets 범위에 RAW 값을 쓸 수 있음. 최대 10,000행·행당 256셀·요청 1MB 제한을 적용
- 프로젝트 실행 코드에서 `weblink_api.import_csv_to_sqlite(...)`, `import_json_to_sqlite(...)`로 프로젝트에 추가한 UTF-8 CSV·JSON 파일을 프로젝트별 SQLite 테이블로 가져올 수 있음. 파일 200KB·10,000행 제한, 테이블/열 이름 정리, SQL 파라미터 바인딩, 실패 시 기존 테이블 보존을 적용
- 프로젝트 가져오기에서 Google Drive CSV·JSON 여러 파일을 고르면 프로젝트 DB와 테이블 가져오기 코드를 생성할 수 있음. 생성된 `main.py`에서 기존 `weblink_api` 가져오기 도구를 사용하며, 사용자가 실행을 눌러 `/data/imported_data.db`에 저장
- 프로젝트 대시보드를 문서와 진행 상황의 균형 잡힌 2열 레이아웃으로 재구성하고 README 본문 칼럼을 가운데 배치하되 글은 왼쪽 정렬. 준비 체크리스트는 접힌 상태로 시작해 처음 화면의 정보량과 중복을 줄임
- 프로젝트 대시보드의 파일·작업·팀원·저장 버전 요약을 해당 작업 화면으로 이동하는 바로가기로 변경
- 프로젝트 대시보드에서 작업 완료율, 기한 초과 수, 마감이 가까운 미완료 작업을 확인하고 마감 작업을 눌러 작업 보드의 상세 항목으로 이동
- 프로젝트 소유자 대시보드에 소개·README·첫 작업·팀원 공유·이 컴퓨터 폴더 연결 준비 체크리스트와 해당 기능 바로가기를 제공
- Chrome·Edge에서 프로젝트 전용 컴퓨터 폴더를 WebLink와 연결하고, 로컬 파일 가져오기·내보내기를 할 수 있음
- 로컬 폴더는 브라우저 권한으로만 기억하며 GitHub Desktop의 저장소를 연결하면 파일을 커밋·푸시해 협업할 수 있음. GitHub 자동 업로드·양방향 동기화는 아직 없음
- 로컬 폴더 동기화는 서버 초안 버전을 먼저 확인해 충돌 시 로컬 파일을 덮어쓰지 않으며, `.git`, `.env`, 개인 키 등은 복사하지 않음
- 프로젝트 편집 중 실행·리비전·버전 저장·ZIP·탐색 동작은 초안을 먼저 저장하며, 변경 없는 초안과 동일 리비전의 저장 버전은 중복 생성하지 않음
- 프로젝트 카드/작업 화면에서 프로젝트 전체를 삭제하고, 저장 버전은 개별 삭제 가능. 프로젝트 SQLite Docker 볼륨 정리는 worker 큐에서 재시도
- 저장된 프로젝트 파일 ZIP 내려받기, 사용자 프로젝트 접근 검증 및 환경 비밀 파일 제외

## Google Sheets 연결 확인 결과

2026-09-28 로컬 환경에서 사용자의 Google OAuth 계정 연결을 완료했다. 테스트용 Google Sheets에 가상 샘플 표를 입력하고 WebLink의 연결 화면에서 한국어 기본 탭의 `시트1!A1:D4` 범위를 읽어 네 행의 데이터를 확인했다.

프로젝트 코드에서는 다음 함수를 사용할 수 있다.

```python
from weblink_api import get_google_sheet

sheet = get_google_sheet("SPREADSHEET_ID", "'시트1'!A1:D4")
rows = sheet["values"]
print(rows)
```

프로젝트 코드는 연결한 계정이 접근 가능한 Google Sheets를 읽고 쓸 수 있다. 쓰기는 코드를 명시적으로 실행할 때만 수행되며 예약된 자동 동기화는 아직 없다.

## 보안 및 권한 범위

- Google OAuth는 Sheets 읽기·쓰기 권한과 Drive Picker에서 직접 선택한 파일을 위한 `drive.file` 권한을 요청한다. 기존 연결은 새 권한에 다시 동의해야 할 수 있다.
- Google refresh token은 Fernet 키로 암호화해 PostgreSQL에 저장한다. `.env`와 암호화 키는 Git에 올리지 않는다.
- Drive Picker는 `drive.file`만 추가 요청해 사용자가 Picker에서 선택한 파일에 접근한다. Google Drive API와 Picker API를 활성화하고 `GOOGLE_PICKER_API_KEY`, `GOOGLE_CLOUD_PROJECT_NUMBER`를 `.env`에 설정해야 한다. 기존 Google 연결은 Drive 권한을 추가하도록 다시 동의해야 할 수 있다.
- 학생 코드 실행 컨테이너는 네트워크가 차단돼 있다. Google 연결이 있는 실행에서만 별도의 고정 목적 연결 서비스가 Google token 및 Sheets API에 접속한다.
- Google Sheets 권한은 특정 셀 범위만으로 제한되지 않는다. 범위 입력은 한 번의 읽기 요청에 사용할 범위이며, 실제 OAuth 권한은 연결한 Google 계정이 접근할 수 있는 스프레드시트에 적용된다.
- 로컬 OAuth 앱은 개발/테스트 용도다. Google Cloud 테스트 사용자와 외부 앱 설정이 필요할 수 있다.

실제 비밀값이 든 `.env`는 공유하거나 커밋하지 않는다. OAuth 설정과 암호화 키는 `.env.example`의 빈 항목에 대응하도록 `.env`에 따로 저장한다.

비공개 GitHub 저장소를 가져오려면 연결 앱에서 Fine-grained personal access token을 연결한다. GitHub에서 사용할 저장소만 지정하고 Repository permissions의 Contents는 Read-only로 둔다. 토큰은 WebLink DB에 암호화해 저장하며 `.env`의 `CONNECTION_ENCRYPTION_KEY`가 필요하다. WebLink 연결을 해제해도 GitHub 토큰 자체는 폐기되지 않으므로 GitHub 설정에서 별도로 삭제한다. 현재 GitHub 기능은 저장소를 새 프로젝트로 가져오는 단방향 복사이며 push/pull 동기화는 지원하지 않는다.

초대 이메일을 보내려면 `.env`에 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`을 설정한다. TLS 서버는 `SMTP_USE_SSL=true` 또는 `SMTP_STARTTLS=true`를 사용한다. 초대 링크의 공개 주소가 localhost가 아니면 `INVITE_WEB_BASE_URL`도 실제 WebLink 주소로 바꾼다. 메일 설정이 없거나 전송에 실패하면 초대는 생성된 채 유지되고 화면에서 링크를 복사해 전달할 수 있다.

## 2026-10-27 · 작업 보드와 팀 관리 정리

- 새 작업 작성과 부가 설정(담당자·우선순위·마감일)은 필요할 때 펼친다. 작성 폼을 접어도 현재 프로젝트의 입력은 유지하며, 서버 등록 성공 시에만 초기화한다.
- 작업 상세를 보드 열 밖의 넓은 영역으로 이동했다. 체크리스트·기존 댓글·댓글 작성과 닫기를 한곳에 두고 활동 기록은 접어 둔다. 상세를 열 때 제목으로 키보드 초점을 이동한다.
- 검색은 항상 보이고 나머지 필터는 접을 수 있다. 적용 조건 수와 결과 개수를 표시하며 검색 결과 없음 안내는 한 번만 표시한다.
- 팀 초대에서 가입 계정 즉시 추가와 링크 수락을 명확히 구분한다. 링크 생성 시 SMTP 설정에 따라 이메일이 발송될 수 있음을 안내하고, 같은 서버에 접속해야 한다는 설명을 보완했다. 보낸 초대·팀 변경 기록은 접어서 볼 수 있다.
- 작업 상세 조회·주기 갱신을 하나의 effect로 통합하고 실패·재시도 상태를 표시한다. 화면을 떠나면 진행 중 조회 결과를 반영하지 않는다. 다른 프로젝트로 이동하면 이전 초대 링크와 작성 입력을 초기화한다.
